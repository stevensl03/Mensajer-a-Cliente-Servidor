REQUERIMIENTOS DE LA APLICACIÓN

I. DESCRIPCIÓN GENERAL
    - Se requiere una aplicación para enviar mensajes a la comunidad académica de la Universidad.
    - Los mensajes pueden contener:
        - Texto.
        - Imágenes.
    - La aplicación de software debe implementar las siguientes funcionalidades.

II. SERVIDOR
    1. Usuarios y autenticación
        - Cada usuario tiene registrado:
            - Código.
            - Nombres.
            - Apellidos.
            - Contraseña.
            - Programa académico.
        - Los usuarios serán validados por:
            - Código.
            - Contraseña.
        - Inicialmente los usuarios estarán registrados en:
            - Un archivo plano, o
            - Una base de datos externa.

    2. Restricción de conexiones
        - Se debe restringir el número de usuarios conectados a la red.
        - Esta restricción se realizará utilizando archivos de configuración.

    3. Almacenamiento y logs
        - La información se almacenará en una base de datos relacional (MySQL).
        - Se deben utilizar archivos de configuración para configurar la conexión a la base de datos.
        - Se deben registrar los logs de los mensajes enviados entre los usuarios.
        - Los logs se almacenarán en una base de datos relacional.
        - Adicionalmente, se debe guardar en un directorio toda la información enviada por los usuarios.

    4. Estructuras de datos
        - Todos los mensajes deben almacenarse en una o más estructuras de datos.
        - Desde allí se debe consultar la información de los mismos.

    5. Procesamiento de mensajes recibidos
        - Texto:
            - Obtener hash con SHA256.
            - Contar los caracteres.
            - Contar las palabras.
        - Imágenes:
            - Obtener hash con SHA256.
            - Aplicar filtros:
                - Escala de grises.
                - Sepia.
                - Girar 180 grados.
                - Brillo.
                - Reducción de tamaño.
            - Cada filtro genera una nueva imagen que se debe almacenar.
            - Los filtros se deben ejecutar secuencialmente.

    6. Comunicación y conexiones
        - El servidor debe seguir la arquitectura indicada en el diagrama.
        - Enviar mensajes a todos los usuarios.
        - Un usuario se puede conectar más de una vez.
        - Cerrar conexiones de los usuarios.
        - Se debe mostrar la información de cada mensaje que llega por la consola.

    7. Informes de usuarios
        - Usuarios registrados.
        - Usuarios conectados, indicar la cantidad de veces.
        - Listado de mensajes enviados.
            - Detalle de cada mensaje.
        - Logs generados.

III. CLIENTE
    1. Funcionalidades
        - Puede ver qué usuarios estarán conectados.
        - Todos los usuarios son visibles a la comunidad.
        - Se podrá intercambiar mensajes (texto o archivos) con un usuario específico.

    2. Persistencia
        - La información se almacenará en una base de datos relacional local (H2Database).
        - Se deben utilizar archivos de configuración para configurar la conexión.

IV. ASPECTOS GENERALES
    1. Tipo de aplicación
        - La aplicación cliente y servidor pueden ser aplicaciones de escritorio.
        - Se requiere crear aplicaciones con capas y con componentes.

    2. Lenguajes
        - Los clientes pueden ser programados en lenguajes de programación diferentes a Java.

    3. Comunicación
        - El protocolo de comunicación entre cliente/servidor será TCP-IP.

    4. Principios de diseño
        - Se deben aplicar los principios de diseño:
            - Inversión de dependencias.
            - Inyección de dependencias.
            - Fábricas de objetos.
            - Entre otros.
